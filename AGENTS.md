# AVIOR UX — инструкции для работы с проектом

Сначала прочитай `docs/STATE.md`, `docs/STRATEGY.md`, `docs/DECISIONS.md`, `docs/HANDOFF.md`, затем проверь текущую ветку и изменения. Отвечай пользователю по-русски.

Цель — развить услуги разработки сайтов и продвижения, проверить спрос и экономику на собственном AVIOR UX. Целевая аудитория — владельцы сервисных центров и ремонтных мастерских: смартфоны, ноутбуки, электросамокаты, бытовая техника. Ищем заказчиков сайта и продвижения для их бизнеса. Запросы конечных потребителей ремонта не считать спросом на наши B2B-услуги; широкий бизнес услуг не является согласованной целевой аудиторией. Разделяй наблюдения, гипотезы и согласованные решения. Примеры конверсии не являются статистикой рынка. Не придумывай частотности, стоимость клика и продажи.

Работай в отдельной ветке под одну задачу, с конкретными коммитами и PR. Перед изменением общих файлов обнови сведения о ветке main. При параллельной работе моделей используй отдельные ветки/рабочие копии. Не перезаписывай чужие изменения. Не делай force-push. Согласование одной модели с другой не равно решению пользователя.

После работы обновляй STATE и HANDOFF: выполненное, проверки, блокеры, следующие шаги, используемая ветка. Решения пользователя записывай в DECISIONS; предложения — в STRATEGY. Не копируй целиком переписку.

Репозиторий публичный. Не коммить API-ключи, токены, клиентские контакты, переписки, сырые отчёты и внутреннюю экономику. Рабочие данные держи вне репозитория. В инструкции можно ссылаться на приватный источник без публикации его содержимого.

Не запускай платные API-вызовы без согласованного ограничения расходов. Не меняй рекламные бюджеты и не публикуй сайт автоматически в рамках исследования спроса. В Wordstat счётчики пересекаются: не складывай их как уникальную аудиторию. Дешёвые переходы не означают дешёвые продажи.

Для сборщика: Python 3.10+, `python tools/demand/wordstat_collect.py --plan`. Живой API требует отдельной настройки. Для сайта команды находятся в package.json (`npm run build`). Выбирай проверки по изменённой части и честно указывай, что не запускалось.

## Общий сервер: изоляция AVIOR UX

Постоянное требование пользователя от 07.11.2026: на сервере много других проектов; главное — не задеть их. Наличие SSH-доступа root не расширяет область задачи.

- Для `ux.avior.moscow` подтверждены исходники `/var/www/ux-src`, публикация `/var/www/ux-src/dist`, конфигурация `/etc/nginx/sites-enabled/ux`. Адрес, логин и расположение ключа хранить в приватной передаче, не в публичном Git.
- Перед изменением сервера повторно проверить домен, фактический document root, символьные ссылки, ветку и локальные изменения. Не перезаписывать серверные изменения; не выполнять `git reset --hard` и `git clean` ради деплоя.
- Изменения и резервные копии ограничивать AVIOR UX. Перед удалением, перемещением и синхронизацией проверить разрешённый абсолютный путь; не выполнять рекурсивные операции над `/var/www`, общими каталогами и масками соседних сайтов. Не применять `rsync --delete` к общему родительскому каталогу.
- Не менять соседние сайты, CMS, магазин, n8n, базы данных, Docker-контейнеры, чужие сертификаты, cron, пользователей, firewall, системные пакеты и общие настройки Nginx. Не останавливать и не перезапускать общие службы ради публикации статических файлов UX.
- Сначала подготовить и проверить сборку и способ отката в пределах UX. Изменение общей инфраструктуры — отдельная задача с явным разрешением пользователя. Исследование Wordstat не является разрешением на публикацию лендинга.
