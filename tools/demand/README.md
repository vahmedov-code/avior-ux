# AVIOR: исследование спроса, версия 0.1

Сборщик официального Wordstat API через Yandex Search API. Python 3.10 или новее, дополнительных пакетов нет. Подготовлен 7 ноября 2026. Реальные частотности пока не собраны: ключ и каталог не подключены. Программа не настраивает рекламу и не пополняет счета.

## Запуск

1. Установить Python, распаковать архив и открыть терминал в его папке.
2. Проверить план: `python wordstat_collect.py --plan` (никаких сетевых запросов).
3. В Yandex Cloud настроить каталог и сервисный аккаунт с ролью `search-api.webSearch.user`, API-ключом с областью `yc.search-api.execute`. Предварительно проверить текущие тарифы и квоты. Лимит скрипта ограничивает число вызовов, не денежный расход. Создание и оплату облачных ресурсов этот пакет не выполняет.
4. Задать локально переменные `YANDEX_API_KEY` и `YANDEX_FOLDER_ID`. Ключ не передавать в чат, не сохранять в архив или репозиторий.
5. Выполнить `python wordstat_collect.py`. По умолчанию до 30 новых API-вызовов за запуск; план содержит 22 вызова. Автоповтора при ошибке нет. Успешные ответы остаются в кеше; повторный запуск продолжает сбор. Итоговые CSV создаются после полного прохода.
6. Прикрепить папку результатов архивом в чат. Ключей в ней нет.

PowerShell, пример переменных (ввести свои значения только локально):

```powershell
$env:YANDEX_API_KEY = Read-Host 'API key'
$env:YANDEX_FOLDER_ID = Read-Host 'Folder ID'
python wordstat_collect.py
Remove-Item Env:YANDEX_API_KEY
```

## Что получим

- `candidates.csv`: запросы и ассоциации с эвристической пометкой для ручной проверки. Пометка не доказывает коммерческое намерение. Ничего автоматически не удаляется.
- `seed_totals.csv`: широкая частотность исходных фраз за последние 30 дней.
- `cities.csv`: распределение каждой исходной фразы по городам (ID Яндекса). Отчёт API глобальный; для сравнения российского рынка оставить российские города. Нельзя смешивать города и области или считать индекс интереса показателем прибыли. Для расшифровки ID используйте официальное дерево регионов (ссылка ниже).
- `metadata.json`: настройки и ограничения интерпретации.
- Отдельный кеш содержит сырые ответы и время их получения. Новая папка `--cache wordstat-cache-new` даёт новый срез. Старый кеш не обновляется автоматически; при сравнениях учитывать даты.

Сравниваем четыре предложения: сайт сервисному центру, сайт бизнесу услуг, продвижение существующего бизнеса, сайт с рекламой. В первой итерации собираем по России; во второй в `regions` задаём отдельные наборы для выбранных городов и повторяем сбор. Кандидаты не гарантируют спрос: исходные маски — гипотезы.

## Как интерпретировать

Не суммировать частотности пересекающихся фраз: это не уникальные пользователи и не число заказчиков. Похожие запросы могут относиться к чужим услугам или обучению. Широкая частотность не равна точной: перспективные фразы перепроверяем операторами в Вордстате. Частоту в регионах не складываем, если регионы вложены.

Wordstat не даёт цену клика. После ручной очистки загружаем коммерческие кандидаты в Прогноз бюджета Директа, отдельно по регионам. Затем ограниченный рекламный тест проверяет стоимость качественной заявки и оплаты. Нельзя обещать поток клиентов на основании одних частотностей.

Низкая частотность не означает низкую конкуренцию. Коммерческие длинные запросы, близкие к нашему продукту, — кандидаты для проверки. Информационные запросы — отдельный эксперимент с отдельной страницей и бюджетом, а не смесь с поиском готовых заказчиков.

## Проверка

Локально проверены разбор ответов, повторное использование кеша, остановка по лимиту, защита CSV от формул. Живой API без ключа не проверен. При смене схемы API потребуется обновление.
