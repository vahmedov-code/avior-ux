# AVIOR: сбор спроса Wordstat, версия 0.2

Python 3.10+, только стандартная библиотека. Работает с официальным Yandex Search API. Ключ вводится локально, не передаётся в чат и не записывается в Git. Кеш, CSV, metadata и подробные отчёты хранить вне репозитория.

## Запуск из корня репозитория

Проверка плана без сети:

```powershell
python tools/demand/wordstat_collect.py --config tools/demand/research-repair-leads.json --plan --max-calls 150
```

Живой запуск с внешними папками:

```powershell
python tools/demand/wordstat_collect.py --config tools/demand/research-repair-leads.json --prompt-credentials --max-calls 150 --timeout 45 --retries 2 --retry-delay 2 --passes 2 --cache ../wordstat-leads-cache --out ../wordstat-leads-results
```

Нужны каталог Yandex Cloud, сервисный аккаунт с ролью `search-api.webSearch.user` и API-ключ с областью `yc.search-api.execute`. Переменные YANDEX_FOLDER_ID и YANDEX_API_KEY можно задать локально. `--prompt-credentials` спрашивает отсутствующие значения в интерактивном терминале, скрывает ввод ключа и не сохраняет его в файлы/постоянные переменные Windows. Пустой ключ или отсутствие скрытого ввода останавливают запуск до сетевого запроса.

В локальном launcher пользователя Folder ID берётся из первого успешного кеша, поэтому вводится только ключ. Отсутствие сохранённого ключа означает, что новый процесс потребует его заново. Не читать буфер обмена и не извлекать ключ из чужих процессов.

## Устойчивость к сетевым сбоям

Сначала собираются основные частотности всех фраз/регионов, затем распределения городов. Один неответивший запрос городов не блокирует основные частотности и остальные фразы.

- По умолчанию `--retries 2`: до двух повторов временного сбоя, всего до трёх попыток одного запроса в одном проходе. Поддерживаются сетевые обрывы/таймауты/усечённый ответ и HTTP 408/429/500/502/503/504.
- Паузы увеличиваются: при retry-delay 2 это 2 и 4 секунды. Числовой Retry-After учитывается; если сервер требует ждать больше 60 секунд, инструмент останавливается и сохраняет кеш.
- Ожидание увеличивается по попыткам, максимум 300 секунд. При timeout 45 это 45, 90 и 135 секунд. Ошибка доступа, неверные параметры, непроверенный TLS-сертификат и некорректные данные не повторяются автоматически.
- После исчерпания повторов запрос откладывается; остальные продолжаются. `--passes 2` разрешает второй проход по отсутствующим ответам в том же процессе, без повторного ввода ключа. Готовые ответы берутся из кеша.
- `--max-calls` — общий предел **всех HTTP-попыток**, включая ошибки, повторы, бесплатное дерево, пробу и все проходы. Между проходами счётчик не сбрасывается. В новом запуске предел новый; учитывать стоимость всего действия, а не только одного запроса.
- Для старого поведения доступны `--retries 0 --passes 1`, но частичные результаты теперь всё равно сохраняются при временных сбоях.

Нельзя гарантировать ответ внешнего API. При длительной недоступности результат остаётся явно частичным; ошибок не скрывать и не подставлять нули вместо отсутствующих ответов.

## Полный и частичный результат

Коды завершения:

| Код | Значение |
|---|---|
| 0 | Весь план завершён, metadata.complete = true |
| 1 | Ошибка доступа, параметров, данных, отмена ввода или другая критическая ошибка |
| 2 | Сохранены частичные CSV, metadata.complete = false; список пробелов в pending_requests |

Наличие metadata.json само по себе больше не означает полный сбор. Launcher проверяет complete: частичный результат можно продолжать, полный повторно не запускается. Старые metadata, созданные только после полного прохода и не имевшие поля complete, считаются завершёнными для совместимости.

Каждый успешный ответ атомарно сохраняется в кеше. Для продолжения нужны те же параметры, каталог и кеш. Не менять Folder ID и не удалять успешный кеш. Неуспешные запросы в CSV отсутствуют и перечислены в pending_requests: это неизвестная частотность, не нулевой спрос.

## Файлы

- candidates.csv: уточнения и ассоциации, эвристические пометки требуют ручной проверки. Строки защищены от исполнения формул при открытии в табличных приложениях.
- seed_totals.csv: широкие частотности исходных масок за последние 30 дней. Опущенные нулевые скаляры успешного proto3-ответа нормализуются в 0; не путать с сетевым пробелом.
- cities.csv: глобальное распределение по городам, не только Россия.
- regions_tree.json: официальное дерево при collect_region_tree=true, названия/проверка ID и фильтрация России. Столицы вложены в агломерации, не суммировать их.
- metadata.json: статус complete, pending_requests, попытки API текущего процесса, покрытие top_responses/city_responses, конфиг и ограничения.

Частотности пересекаются, не складывать как уникальную аудиторию. Это не клики, покупатели или продажи. Ассоциации не считать прямым спросом. Wordstat не даёт CPC/CAC; после очистки нужен прогноз Директа и ограниченный тест.

## Исследовательские конфиги

- research.json: первый срез, 11 фраз, до 22 ответов.
- research-repair-expanded.json: 40 фраз × 5 наборов регионов, 40 distributions и дерево, до 241 успешного ответа до учёта повторов.
- research-repair-leads.json: 8 фраз × 5 наборов регионов, 8 distributions и дерево, до 49 успешных ответов. Локальный запуск продолжения ограничен 150 попытками, включая повторы: по проверенным 07.11.2026 тарифам даже консервативная оценка 150 × 0,05 ₽ = 7,50 ₽ новых расходов за этот запуск, внутри разрешённого порога. Готовые ответы не отправляются снова.

Правила расходов в AGENTS/DECISIONS. Новую папку кеша использовать только для нового среза, а не при возобновлении. Не выдавать изменения дат/семантики за тренд рынка.

## Проверки

```powershell
python -m unittest discover -s tools/demand -p test_wordstat_collect.py -v
```

27 автономных тестов: кеш, нулевые proto3-ответы, HTTP-классификация, Retry-After, нарастание пауз/таймаутов, общий предел всех попыток, второй проход с одним вводом ключа, частичные CSV, запрет подстановки нуля вместо сбоя, продолжение из кеша, офлайн-режим и отсутствие ключа в диагностике/кеше. Живые API-тесты не выполняются без локального ввода ключа.
